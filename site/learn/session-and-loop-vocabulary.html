Turn, step, round: the session vocabulary

BeginnerLearn the basicsabout 6 min read

Code version: DeepSeek Harness @ ce7073d · 2026-10-30

Before you read

This page uses ideas from these pages:

  • Everything is a plugin: Cordis Beginner
  • Profiles and bundles: how a running dsh tree is assembled Beginner

In one sentence

A session has turns, a turn has steps, and the agent loop appends each turn or step boundary to the session log.

The idea#

A session counts its own work with a small, fixed vocabulary (docs/glossary.md:35-40). A turn is one drain of admitted input (docs/glossary.md:37). It opens before the first input is claimed, and it closes once nothing is owed (docs/architecture.md:81). A step is one model request plus the tool calls its response causes. One turn has zero or more steps (docs/glossary.md:38, docs/architecture.md:81).

An everyday comparison. Think of a turn as one visit to a service counter. It stays open from the moment you are called until the clerk has nothing left to do for you. A step is one question you ask, and the paperwork it causes. The comparison stops here. A real clerk does not keep a permanent, numbered record of each step. The session does: the loop appends a start event and an end event for each step.

The picture#

Read panel 2 left to right: the loop opens and closes a turn, and opens and closes each step inside it. It does this by appending one named event for each boundary. The session log on the right keeps every one of them, in order. Panel 1 names the pieces that build the agent this loop belongs to; The agent loop and the session log reads it in detail.

In DeepSeek Harness#

The agent loop's turn() method opens a turn by appending a turn/start event before it claims any input (packages/core/agent-loop/src/agent.ts:334-336).

Not every turn spends a step. When the turn's first claim has an empty message list, the loop ends the turn as completed and returns. A listener can make the list empty, for example when it removes the waking message. The loop does not append a step/start event in this case (packages/core/agent-loop/src/agent.ts:354-361).

A round sits outside a turn: it is an outer policy iteration, such as a goal round, that contains one turn (docs/glossary.md:39). The goal-round driver reserves at most one next round at a time (packages/goal/goal-round-driver/src/index.ts:145). Each round queues one goal prompt as a user message that carries the round number (packages/goal/goal-round-driver/src/index.ts:190-195). An exchange is a run of consecutive turns, from a turn whose first step admits human input until the next such turn (docs/glossary.md:40). The chat client (dsh-client-ui-chat) uses the same grouping: an opening turn starts an exchange (packages/client/ui-chat/src/client/contract/group-tree.ts:6-7). The chat keeps the latest exchange expanded (docs/glossary.md:40).

The loop appends each of these events through one method: Session.append() (packages/core/session/src/index.ts:806). It assigns the event the next sequence number, taken from the log's current length (packages/core/session/src/index.ts:827-833).

The agent loop and the session log reads this same loop and log in more detail, including which object builds the agent that runs it.

More detail#

A round's cap is a real config knob, not a fixed number. GoalService declares a defaultMaxGoalRounds setting, with a schema default of 256 (packages/goal/goal/src/index.ts:239-240). A new goal that sets no cap of its own gets this default when it is created (packages/goal/goal/src/index.ts:211-214, packages/goal/goal/src/index.ts:250-251). When a goal reaches its cap, the driver blocks the goal with the code round-limit (packages/goal/goal-round-driver/src/index.ts:182-187). An exchange has no such knob. The glossary defines it only from turn boundaries, and the chat client groups turns from that rule (docs/glossary.md:40).

For the full generated service and event reference, see the repository's own docs/subsystems/core.md and docs/subsystems/session.md.

What can go wrong#

Do not assume a logged turn called the model

Check for a logged step/start event before you assume the model was called. A turn can close as completed with no step at all, only when its first claim has an empty message list (packages/core/agent-loop/src/agent.ts:356-359).

Simplified

This page only names the words. It leaves out the other reasons a turn can end, such as a blocked input, an error, a cancellation, or a max-tokens limit. The agent loop and the session log covers those.

Why it matters. Code that reads the session log to count an agent's work must use the right unit. Do not count turns when the question is about model calls: count steps instead.

Check yourself#

  1. 1
    How many steps can one turn have?
    easy
    Show answer

    Zero or more. A step is one model request plus the tool calls its response causes, and a turn contains zero or more of them (docs/glossary.md:38, docs/architecture.md:81).

  2. 2
    What is the difference between a step and a round?
    medium
    Show answer

    A step is inside a turn: one model request plus its tool calls. A round is outside a turn: an outer policy iteration, such as a goal round, that contains one turn (docs/glossary.md:38-39).

  3. 3
    Which event does turn() append before it claims the turn's first input?
    medium
    Show answer

    turn/start. The loop appends it immediately after it computes the turn number, before it claims any input (packages/core/agent-loop/src/agent.ts:334-336).

  4. 4
    A turn's first claim rewrites to an empty message list. Does the loop still log a step/start event?
    hard
    Show answer

    No. On the turn's first claim, the loop ends that turn as completed and returns. It does not append a step/start event (packages/core/agent-loop/src/agent.ts:356-359).
