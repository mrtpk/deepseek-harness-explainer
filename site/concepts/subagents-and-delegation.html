Subagents and delegation

IntermediateDeepSeek Harness conceptsabout 7 min read + 1 min deep dives

Code version: DeepSeek Harness @ ce7073d · 2026-10-30

Before you read

This page uses ideas from these pages:

  • The agent loop and the session log Intermediate

In one sentence

A parent agent delegates a task to a child through a named provider registered on ctx.subagents.

The idea#

ctx.subagents does not run children itself. It is a named-provider registry: each backend registers under a unique name, and a parent picks one by name when it starts a child (packages/subagent/subagent/src/index.ts:193-200, packages/subagent/subagent/src/index.ts:549-568). One shared SubagentManager gets both the local and the external start path. Every child shares admission, cancellation, ownership and discovery, no matter which provider started it (packages/subagent/subagent/src/index.ts:212-221, packages/subagent/subagent/README.md:12).

An everyday comparison. Think of a dispatcher who hands a job to one of several outside contractors by name. Some contractors stay on call and take a follow-up job later; others do the one job and close the file. The comparison stops here. The dispatcher also fixes what each contractor may touch before the job starts. The contractor cannot widen that scope from inside the job.

The picture#

Read panel 1 from left to right. The caller names a provider, and the registry finds it. Read panel 2 as two separate families: the left lane's children can receive a later message; the right lane's children cannot. The legend under the diagram names the two families.

In the code#

Step 1: startActivation() resolves the named provider, then checks its capabilities#

startActivation() looks up the provider and rejects each requested capability that the provider does not declare. It also checks that the parent is the exact live agent. Then it gives the work to the manager's local or external start path (packages/subagent/subagent/src/index.ts:271-286). The delegation tool in the parent session is the usual caller (packages/subagent/tool-subagent/src/index.ts:324).

Step 2: method presence on the provider decides local or external#

A provider that implements prepareContinuable() seeds a local, resumable child session. One that implements only start() returns a single execution handle and accepts no later message (packages/subagent/subagent/src/types.ts:340-355). The in-process spawn and fork providers both implement prepareContinuable() (packages/subagent/subagent-spawn-in-process/src/index.ts:50, packages/subagent/subagent-fork-in-process/src/index.ts:72). The claude-code, codex, acp and dsh-sdk providers each implement only start() (packages/subagent/subagent-claude-code/src/index.ts:73-116, packages/subagent/subagent-codex/src/index.ts:73, packages/subagent/subagent-acp/src/index.ts:92, packages/subagent/subagent-dsh-sdk/src/index.ts:134).

Step 3: the Claude Code provider runs the official SDK, not the host's own CLI#

dsh ships a Claude Code subagent provider. Each run calls the official Claude Agent SDK's query() (packages/subagent/subagent-claude-code/src/run.ts:441). The run also gives the SDK a custom spawn callback. This callback starts the SDK's real Claude Code CLI process through ctx.subprocess, the shared subprocess owner (packages/subagent/subagent-claude-code/src/run.ts:370-375, packages/subagent/subagent-claude-code/src/index.ts:100-114).

Not the host's installed claude

The provider never falls back to a claude executable already on the host; the SDK starts its own platform-pinned runtime on demand (packages/subagent/subagent-claude-code/README.md:12).

Step 4: tool restriction for a delegated scope#

A tool restriction is an allow/deny name list applied with ctx.tools.restrict() on the child's own scope (packages/core/tools/src/contracts.ts:376-381, packages/core/tools/src/index.ts:162-189). The subagent package still makes this call in one case. When an older child cold-resumes, the package applies the historical toolFilter from that child's descriptor (packages/subagent/subagent/src/child-agent.ts:217, packages/subagent/subagent/src/manager.ts:1395). For a new child, the delegation tool does not accept its old persona and toolFilter config fields. An Agent Preset, selected with agentPreset, now sets the tools and the persona (packages/subagent/tool-subagent/src/index.ts:151-154).

More detail#

Two numeric limits apply before a child starts. The default delegation depth is 1. resolveMaxDepth() gets the limit for each call. It returns undefined (no host-enforced cap) only when the tool sets 'provider-managed' (packages/subagent/subagent/src/index.ts:196, packages/subagent/subagent/src/index.ts:244-250). A child's depth is the parent's depth plus one (packages/subagent/subagent/src/child-agent.ts:49-58). The parent's depth is the larger of the persisted session-header value and the runtime option. Thus a resumed child cannot delegate as if it were top-level (packages/subagent/subagent/src/depth.ts:28-36). Separately, maxActiveSubagents (default 8) limits the live local children that share one parent pool (packages/subagent/subagent/src/index.ts:187-197, packages/subagent/subagent/src/manager.ts:743-744).

A delegated child's permission scope is fixed at the moment it starts. The code captures the parent's state before the child start's first await (packages/subagent/subagent/src/child-agent.ts:237-255). It copies the parent's explicit sandbox-mode override, if one exists. It copies the parent's permission preset only when that preset is auto or danger-full-access. When the approval service is present, it pins the child's approval policy to 'never', whatever the parent's policy is. The code then appends these values to the child's own log, after any fork seed. Thus the child's log alone shows its effective policy (packages/subagent/subagent/src/child-agent.ts:257-279).

Every in-process child also gets one fixed delegation-scope text in its runtime context. The text tells the child that its scope cannot widen from inside the session (packages/subagent/subagent/src/child-agent.ts:171-175, packages/subagent/subagent/src/child-agent.ts:204-209).

For the full generated service and event reference, see the repository's own docs/subsystems/subagent.md.

Deep dive

The four start-time capabilities a provider can declare

Before the manager prepares a child, the service rejects the first requested field that the provider's capabilities does not support (packages/subagent/subagent/src/index.ts:632-653):

CapabilityRequested byMeaning
agentOptionsrequest.agentOptionsPer-child provider/model/reasoning-effort overrides (packages/subagent/subagent/src/types.ts:124).
agentPresetrequest.agentPresetA preset that is independent of the parent's own composition (packages/subagent/subagent/src/types.ts:126). The service also rejects it when the provider inherits the parent context (packages/subagent/subagent/src/index.ts:634).
outputSchemarequest.outputSchemaA structured, schema-validated final result (packages/subagent/subagent/src/types.ts:127).
depthLimitrequest.maxDepthA host-enforced numeric delegation-depth cap (packages/subagent/subagent/src/types.ts:128).

What can go wrong#

persona and toolFilter no longer load on the delegation tool

A dsh-tool-subagent configuration that sets persona or toolFilter fails at plugin load. Put the tools and the persona in an Agent Preset. Select the preset with agentPreset (packages/subagent/tool-subagent/src/index.ts:151-154).

Simplified

This page leaves out child discovery and catalogs, sendMessage() adjacency rules, interrupting a running child, and the ACP, Codex and DSH SDK provider transports.

Why it matters. An old configuration with toolFilter does not load (packages/subagent/tool-subagent/src/index.ts:151-154). Only the cold-resume path of an older child still applies a recorded toolFilter (packages/subagent/subagent/src/child-agent.ts:160-163).

Check yourself#

  1. 1
    Which two providers in this codebase give a child a durable, resumable session?
    easy
    Show answer

    spawn and fork, the only providers that implement prepareContinuable() (packages/subagent/subagent-spawn-in-process/src/index.ts:50, packages/subagent/subagent-fork-in-process/src/index.ts:72).

  2. 2
    Does the Claude Code subagent provider run the host machine's own installed claude command?
    medium
    Show answer

    No. It calls the official Claude Agent SDK's query(). The SDK starts its own platform-pinned CLI process through dsh's subprocess owner. It never falls back to a host executable (packages/subagent/subagent-claude-code/README.md:12, packages/subagent/subagent-claude-code/src/run.ts:370-375).

  3. 3
    A tool configures maxDepth: 'provider-managed'. What does resolveMaxDepth() return?
    medium
    Show answer

    undefined: no host-enforced numeric cap. The provider's own runtime owns the recursion budget instead (packages/subagent/subagent/src/index.ts:244-245, packages/subagent/tool-subagent/src/index.ts:76-80).

  4. 4
    A request sets outputSchema, but the named provider's capabilities.outputSchema is false. What happens?
    hard
    Show answer

    startActivation() throws UNSUPPORTED_CAPABILITY before a child starts. assertCapabilities() rejects the first requested field that the provider does not support (packages/subagent/subagent/src/index.ts:632-653, packages/subagent/subagent/src/types.ts:127).
