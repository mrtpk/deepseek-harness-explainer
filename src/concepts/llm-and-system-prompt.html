The idea

Every model call in {{project name}} goes through one service: ctx.llm. ctx.llm does not talk to a provider itself. A plugin called a {{term provider-adapter | provider adapter}} does that work. ctx.llm only picks the adapter registered for the request's provider name ({{cite packages/llm/llm/src/index.ts:401}}).

Before the loop calls ctx.llm, it builds that request's {{term system-prompt | system prompt}}. Plugins register ordered sections with ctx.systemPrompt. One assembly call joins them into text for the current step ({{cite packages/core/agent-loop/src/agent.ts:294}}).

An everyday comparison. Think of ctx.llm as a phone switchboard. You dial a provider's name, and the switchboard connects you to the one line registered for it. The system prompt is a briefing note read onto the call first. The comparison stops here. A real briefing note never changes between calls; the system prompt can, because a section's text can depend on the current step.

In the code

Step 1: ctx.llm routes stream() to the adapter registered for one provider name

A provider adapter extends the abstract LlmAdapter class and registers itself with ctx.llm.registerAdapter(providers, adapter) ({{cite packages/llm/llm/src/index.ts:401}}). DeepSeekAdapter is one such adapter; it registers like this ({{cite packages/llm/llm-deepseek/src/host.ts:81}}, {{cite packages/llm/llm-deepseek/src/adapter.ts:22}}).

Step 2: the agent assembles the system prompt before it builds the request

Each step's preStep() calls ctx.systemPrompt.assemble() with the step's model selection and the tools admitted for that step ({{cite packages/core/agent-loop/src/agent.ts:294}}). renderPrompt() then turns that assembly into plain text ({{cite packages/core/agent-loop/src/agent.ts:442}}).

Step 3: the rendered prompt is committed to the session, not sent as a hidden field

systemPrompt.project(renderedPrompt, ...) works out what changed since the last step. The loop appends every commit as a system/message session event ({{cite packages/core/agent-loop/src/agent.ts:453-461}}). The system prompt reaches the model as logged history, not as a field only the request carries ({{cite docs/architecture.md:112}}).

Step 4: buildRequest() derives the history and streams the frozen request

buildRequest() logs a request/header only on the agent's first step, or when the config or tool list changed since the last one ({{cite packages/core/agent-loop/src/agent.ts:675-688}}). It then derives the model-visible message list from the session log with session.deriveMessages() ({{cite packages/core/agent-loop/src/agent.ts:728}}). The step then streams the frozen request through ctx.llm.stream() ({{cite packages/core/agent-loop/src/agent.ts:490}}).

More detail

registerAdapter() takes every provider name an adapter owns and registers them together, all at once. If any one of those names is already taken, the whole call fails with DUPLICATE_ADAPTER and nothing registers ({{cite packages/llm/llm/src/index.ts:395}}, {{cite packages/llm/llm/src/index.ts:443}}). ctx.llm.stream() itself runs inside an llm/stream waterfall. A plugin can wrap every call for retry or logging before it reaches the resolved adapter ({{cite packages/llm/llm/src/index.ts:1170-1183}}).

A prompt section's order decides where its text lands; sections join in ascending order, and a duplicate section name in one scope throws ({{cite packages/core/system-prompt/src/index.ts:485-492}}). A section can also declare itself complete: assembly still runs its full waterfall, but then restores that one section as the whole prompt ({{cite packages/core/system-prompt/src/index.ts:75}}).

For the full generated service and type reference, see the repository's own {{cite docs/subsystems/llm-streaming.md}} and {{cite docs/subsystems/system-prompt.md}}.

Most APIs send a system prompt as one field on every request. {{project name}} instead treats it as part of the durable session history. A reader who only reads the session log still sees exactly what the model was told.

By default, a changed prompt replaces the existing system/message event in place, as if it had always said the new text. Only when an adapter's resolved model info sets systemPromptUpdate: 'in-history' does the loop instead append a fresh system/message for each change. That route reads whichever system message is most recent ({{cite packages/core/agent-loop/src/agent.ts:453-454}}, {{cite docs/architecture.md:112}}).

What can go wrong

Only agent.model.select(), called before step preparation, may change the provider, model or reasoning effort. The deprecated agent/request hook throws if its decision disagrees with the selection step preparation already fixed ({{cite packages/core/agent-loop/src/agent.ts:635-640}}).

This page leaves out dsh-llm-retry's retry policy, image-attachment pricing and resizing, and reasoning-effort validation. It also leaves out what happens when no adapter is registered for a request's provider name.

Why it matters. Code that reads the session log to reconstruct a model call must read the system/message event, not assume a fixed, separate system field.

Which method must every provider adapter implement?

stream(). Every other LlmAdapter method has a usable default ({{cite packages/llm/llm/src/index.ts:302}}).

 Does the system prompt reach the model as a hidden request field?

No. The loop commits it as a system/message session event, so it is logged history, not a field the request alone carries ({{cite packages/core/agent-loop/src/agent.ts:453-461}}, {{cite docs/architecture.md:112}}).

 What happens when two provider adapters try to register the same provider name?

The second registration fails with DUPLICATE_ADAPTER. Registration is all-or-nothing across the adapter's whole provider list ({{cite packages/llm/llm/src/index.ts:395}}, {{cite packages/llm/llm/src/index.ts:443}}).

 Can the deprecated agent/request hook change which provider or model a step calls?

No, only when step preparation has not already fixed a selection. agent/request throws if its proposed config disagrees with the provider, model or effort preStep() already selected ({{cite packages/core/agent-loop/src/agent.ts:635-640}}).
