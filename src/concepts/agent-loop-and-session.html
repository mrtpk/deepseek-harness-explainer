The Agent runs the turn/step loop and appends every step to the session's append-only event log. --- An {{term agent}} runs one session's turn/step loop and appends every step to the {{term session-log | session log}}.

The idea

A running dsh agent is not one object that does everything. Three pieces share the work. AgentRegistry is the directory: it knows which agents exist and hands out the one that is registered for a session. The agent itself drives the work: it claims input, calls the model, and runs the tools the model asks for, one {{term turn}} at a time. The session log is the record. The agent appends every turn, {{term step}} and message to the log before it moves on.

An everyday comparison. Think of a help desk. The registry is the phone system that connects you to an agent. The agent is the person who does the work. The log is the ticket system: it records every action the agent takes, in order, before the agent starts the next one. The comparison stops here. A help-desk ticket records work after it happens. The session log is different: the agent reads it back to build its next request to the model.

In the code

Step 1: AgentRegistry delegates creation to the registered factory

AgentRegistry does not build agents itself. Its create() method reads the one factory registered with setFactory() and calls that factory's createAgent() ({{cite packages/core/agent/src/index.ts:416-426}}).

setFactory() throws if a factory is already registered, so only one component can create agents in a given context ({{cite packages/core/agent/src/index.ts:385}}). The agent-loop package is the factory that registers itself ({{cite packages/core/agent-loop/src/index.ts:336}}).

Step 2: the agent-loop factory builds a ReactLoopAgent

AgentLoop implements the factory interface ({{cite packages/core/agent-loop/src/index.ts:291}}). Its createAgent() prepares the session, then builds the new agent through a shared initializeAgent() step, which constructs a ReactLoopAgent for that session id ({{cite packages/core/agent-loop/src/index.ts:717}}, {{cite packages/core/agent-loop/src/index.ts:573}}). ReactLoopAgent is the class that implements the Agent interface ({{cite packages/core/agent-loop/src/agent.ts:112}}).

Step 3: the Agent's turn() loop appends to the session log

Once built, the ReactLoopAgent drives its own work. Its private turn() method opens with a logged turn/start event, then loops over one or more steps until nothing is left to do ({{cite packages/core/agent-loop/src/agent.ts:327-340}}).

Every append, for every event type, goes through the same Session.append() method. It assigns the event the next sequence number, then pushes it onto the in-memory log ({{cite packages/core/session/src/index.ts:526}}, {{cite packages/core/session/src/index.ts:901}}).

More detail

Creation happens in order. AgentRegistry.create() reads the factory and calls createAgent() ({{cite packages/core/agent/src/index.ts:425}}). The agent-loop's createAgent() prepares the session, then hands off to initializeAgent(), which constructs the new ReactLoopAgent ({{cite packages/core/agent-loop/src/index.ts:573}}). From that point, the registry only tracks the live Agent; the ReactLoopAgent instance drives every turn itself.

Inside one turn, each step opens with a logged step/start event. It always closes with a logged step/end event, even if the step throws, because the loop appends step/end in a finally block ({{cite packages/core/agent-loop/src/agent.ts:361}}, {{cite packages/core/agent-loop/src/agent.ts:388}}). The loop runs another step only when the model's step leaves tool work owed, or when new input already arrived. Otherwise, it waits for agent/turn-stopping listeners to settle, then closes the turn with a logged turn/end event ({{cite packages/core/agent-loop/src/agent.ts:395-399}}, {{cite packages/core/agent-loop/src/agent.ts:422}}).

One config knob changes how many tool calls inside a step can run at the same time: maxParallelToolCalls. The loop reads its live value for each step ({{cite packages/core/agent-loop/src/agent.ts:588}}). Its default is 10. The agent-loop package sets this constant once and applies it through its config schema ({{cite packages/core/agent-loop/src/constants.ts:6}}, {{cite packages/core/agent-loop/src/index.ts:296}}). A deployment can change the live value through the agent-loop settings.

For the full generated service and event reference, see the repository's own {{cite docs/subsystems/core.md}} and {{cite docs/subsystems/session.md}}.

"The turn ends" is not one condition. The code has three distinct exits, and each logs a different reason on the turn/end event:

  1. Blocked. Only when a pre-step listener rejects the claimed input: the loop sets reason blocked and stops before running a step ({{cite packages/core/agent-loop/src/agent.ts:348-350}}).
  2. Completed with no step spent. Only on the turn's first claim, when it rewrites to an empty message list: the turn closes as completed with no model call ({{cite packages/core/agent-loop/src/agent.ts:356-358}}).
  3. Normal end. After a step, only when the inbox has no further input: the loop awaits the agent/turn-stopping listeners, then breaks out of the loop ({{cite packages/core/agent-loop/src/agent.ts:395-399}}).

What can go wrong

Check for a logged step before you assume the model was called. A turn can end as completed on its very first claim, only when that claim's input rewrites to an empty message list ({{cite packages/core/agent-loop/src/agent.ts:356-358}}).

This page leaves out tool-call recovery after a failed step, retries, and cancellation. When a step throws, the loop still appends any tool results it already owes before it re-throws the error ({{cite packages/core/agent-loop/src/agent.ts:374-385}}).

Why it matters. Code that reads the session log to reconstruct what the agent did must handle a turn with zero steps.

Which object builds the live ReactLoopAgent: AgentRegistry or the agent-loop factory?

The agent-loop factory (AgentLoop). AgentRegistry.create() only looks up the registered factory and calls its createAgent() ({{cite packages/core/agent/src/index.ts:425}}).

 Does every turn call the model at least once?

No. Only when the turn's first claim is non-empty. A turn can close as completed on its first claim with no step spent, when that claim rewrites to an empty message list ({{cite packages/core/agent-loop/src/agent.ts:356-358}}).

 What happens to the step/end event if a step throws an error?

It is still appended. step/end is logged in a finally block, so it runs whether the step succeeds or throws ({{cite packages/core/agent-loop/src/agent.ts:386-389}}).

 Which config value changes how many tool calls in one step run at the same time, and where is its default set?

maxParallelToolCalls. Its default (10) is a constant in the agent-loop package, applied through its config schema ({{cite packages/core/agent-loop/src/constants.ts:6}}, {{cite packages/core/agent-loop/src/index.ts:296}}), and read live for each step ({{cite packages/core/agent-loop/src/agent.ts:588}}).
