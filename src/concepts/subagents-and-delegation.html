Local providers keep a durable child session; others run once. --- A parent agent delegates a task to a child through a named {{term subagent-provider | provider}} registered on {{term subagent | ctx.subagents}}.

The idea

ctx.subagents does not run children itself. It is a named-provider registry: each backend registers under a unique name, and a parent picks one by name when it starts a child ({{cite packages/subagent/subagent/src/index.ts:193-200}}, {{cite packages/subagent/subagent/src/index.ts:549-568}}). One shared SubagentManager gets both the local and the external start path. Every child shares admission, cancellation, ownership and discovery, no matter which provider started it ({{cite packages/subagent/subagent/src/index.ts:212-221}}, {{cite packages/subagent/subagent/README.md:12}}).

An everyday comparison. Think of a dispatcher who hands a job to one of several outside contractors by name. Some contractors stay on call and take a follow-up job later; others do the one job and close the file. The comparison stops here. The dispatcher also fixes what each contractor may touch before the job starts. The contractor cannot widen that scope from inside the job.

In the code

Step 1: startActivation() resolves the named provider, then checks its capabilities

startActivation() looks up the provider and rejects each requested capability that the provider does not declare. It also checks that the parent is the exact live agent. Then it gives the work to the manager's local or external start path ({{cite packages/subagent/subagent/src/index.ts:271-286}}). The delegation tool in the parent session is the usual caller ({{cite packages/subagent/tool-subagent/src/index.ts:324}}).

Step 2: method presence on the provider decides local or external

A provider that implements prepareContinuable() seeds a local, resumable child {{term session}}. One that implements only start() returns a single execution handle and accepts no later message ({{cite packages/subagent/subagent/src/types.ts:340-355}}). The in-process spawn and fork providers both implement prepareContinuable() ({{cite packages/subagent/subagent-spawn-in-process/src/index.ts:50}}, {{cite packages/subagent/subagent-fork-in-process/src/index.ts:72}}). The claude-code, codex, acp and dsh-sdk providers each implement only start() ({{cite packages/subagent/subagent-claude-code/src/index.ts:73-116}}, {{cite packages/subagent/subagent-codex/src/index.ts:73}}, {{cite packages/subagent/subagent-acp/src/index.ts:92}}, {{cite packages/subagent/subagent-dsh-sdk/src/index.ts:134}}).

Step 3: the Claude Code provider runs the official SDK, not the host's own CLI

dsh ships a Claude Code subagent provider. Each run calls the official Claude Agent SDK's query() ({{cite packages/subagent/subagent-claude-code/src/run.ts:441}}). The run also gives the SDK a custom spawn callback. This callback starts the SDK's real Claude Code CLI process through ctx.subprocess, the shared subprocess owner ({{cite packages/subagent/subagent-claude-code/src/run.ts:370-375}}, {{cite packages/subagent/subagent-claude-code/src/index.ts:100-114}}).

The provider never falls back to a claude executable already on the host; the SDK starts its own platform-pinned runtime on demand ({{cite packages/subagent/subagent-claude-code/README.md:12}}).

Step 4: tool restriction for a delegated scope

A {{term tool-restriction | tool restriction}} is an allow/deny name list applied with ctx.tools.restrict() on the child's own scope ({{cite packages/core/tools/src/contracts.ts:376-381}}, {{cite packages/core/tools/src/index.ts:162-189}}). The subagent package still makes this call in one case. When an older child cold-resumes, the package applies the historical toolFilter from that child's descriptor ({{cite packages/subagent/subagent/src/child-agent.ts:217}}, {{cite packages/subagent/subagent/src/manager.ts:1395}}). For a new child, the delegation tool does not accept its old persona and toolFilter config fields. An Agent Preset, selected with agentPreset, now sets the tools and the persona ({{cite packages/subagent/tool-subagent/src/index.ts:151-154}}).

More detail

Two numeric limits apply before a child starts. The default delegation depth is 1. resolveMaxDepth() gets the limit for each call. It returns undefined (no host-enforced cap) only when the tool sets 'provider-managed' ({{cite packages/subagent/subagent/src/index.ts:196}}, {{cite packages/subagent/subagent/src/index.ts:244-250}}). A child's depth is the parent's depth plus one ({{cite packages/subagent/subagent/src/child-agent.ts:49-58}}). The parent's depth is the larger of the persisted session-header value and the runtime option. Thus a resumed child cannot delegate as if it were top-level ({{cite packages/subagent/subagent/src/depth.ts:28-36}}). Separately, maxActiveSubagents (default 8) limits the live local children that share one parent pool ({{cite packages/subagent/subagent/src/index.ts:187-197}}, {{cite packages/subagent/subagent/src/manager.ts:743-744}}).

A delegated child's permission scope is fixed at the moment it starts. The code captures the parent's state before the child start's first await ({{cite packages/subagent/subagent/src/child-agent.ts:237-255}}). It copies the parent's explicit sandbox-mode override, if one exists. It copies the parent's permission preset only when that preset is auto or danger-full-access. When the approval service is present, it pins the child's approval policy to 'never', whatever the parent's policy is. The code then appends these values to the child's own log, after any fork seed. Thus the child's log alone shows its effective policy ({{cite packages/subagent/subagent/src/child-agent.ts:257-279}}).

Every in-process child also gets one fixed delegation-scope text in its runtime context. The text tells the child that its scope cannot widen from inside the session ({{cite packages/subagent/subagent/src/child-agent.ts:171-175}}, {{cite packages/subagent/subagent/src/child-agent.ts:204-209}}).

For the full generated service and event reference, see the repository's own {{cite docs/subsystems/subagent.md}}.

What can go wrong

A dsh-tool-subagent configuration that sets persona or toolFilter fails at plugin load. Put the tools and the persona in an Agent Preset. Select the preset with agentPreset ({{cite packages/subagent/tool-subagent/src/index.ts:151-154}}).

This page leaves out child discovery and catalogs, sendMessage() adjacency rules, interrupting a running child, and the ACP, Codex and DSH SDK provider transports.

Why it matters. An old configuration with toolFilter does not load ({{cite packages/subagent/tool-subagent/src/index.ts:151-154}}). Only the cold-resume path of an older child still applies a recorded toolFilter ({{cite packages/subagent/subagent/src/child-agent.ts:160-163}}).

Which two providers in this codebase give a child a durable, resumable session?

spawn and fork, the only providers that implement prepareContinuable() ({{cite packages/subagent/subagent-spawn-in-process/src/index.ts:50}}, {{cite packages/subagent/subagent-fork-in-process/src/index.ts:72}}).

 Does the Claude Code subagent provider run the host machine's own installed claude command?

No. It calls the official Claude Agent SDK's query(). The SDK starts its own platform-pinned CLI process through dsh's subprocess owner. It never falls back to a host executable ({{cite packages/subagent/subagent-claude-code/README.md:12}}, {{cite packages/subagent/subagent-claude-code/src/run.ts:370-375}}).

 A tool configures maxDepth: 'provider-managed'. What does resolveMaxDepth() return?

undefined: no host-enforced numeric cap. The provider's own runtime owns the recursion budget instead ({{cite packages/subagent/subagent/src/index.ts:244-245}}, {{cite packages/subagent/tool-subagent/src/index.ts:76-80}}).

 A request sets outputSchema, but the named provider's capabilities.outputSchema is false. What happens?

startActivation() throws UNSUPPORTED_CAPABILITY before a child starts. assertCapabilities() rejects the first requested field that the provider does not support ({{cite packages/subagent/subagent/src/index.ts:632-653}}, {{cite packages/subagent/subagent/src/types.ts:127}}).
