Purpose

This page is a short lookup, not a full catalog. It lists the environment variables, config layers, and command-line flags a reader meets first. For the complete, generated tables, see the repository's own {{cite docs/config-catalog.md}} and {{cite docs/tool-catalog.md}}.

Main environment variables

VariableDefault when unsetWhat it controls
DSH_HOME ~/.dsh ({{cite packages/util/home-paths/src/index.ts:12-18}}) The home {{link learn/profiles-and-bundles | profiles, profile patch files, and user data}} live under. Read by resolveDshHome() ({{cite packages/util/home-paths/src/index.ts:135-137}}).
DSH_AGENTS_HOME ~/.agents ({{cite packages/util/home-paths/src/index.ts:21-27}}) The shared agent configuration root. The filesystem {{term skill}} provider falls back to it for its default skill root ({{cite packages/skill/skill-filesystem/src/index.ts:55}}).
DEEPSEEK_API_KEY (none; the request fails without a key) The default name of the credential the DeepSeek LLM adapter reads its API key from ({{cite packages/llm/llm-deepseek-api-key/src/config.ts:25}}). A {{term plugin}} config can name a different credential instead.
DEEPSEEK_BASE_URL https://api.deepseek.com/anthropic ({{cite packages/llm/llm-deepseek/src/config.ts:115}}) Overrides the DeepSeek endpoint. It applies only when a plugin config does not set baseURL itself. The value must come from a trusted environment layer, not a raw process.env read ({{cite packages/llm/llm-deepseek/src/config.ts:118-119}}, read at {{cite packages/llm/llm-deepseek/src/config.ts:311}}).
HTTP_PROXY / HTTPS_PROXY / NO_PROXY (and the lower-case and ALL_PROXY forms) unset (direct connections) The launcher resolves and installs one proxy policy from these, before the first plugin mounts ({{cite packages/util/http-proxy/src/policy.ts:39-54}}, installed at {{cite apps/cli/src/profile-boot.ts:271-275}}). Node's own fetch does not read the proxy environment on its own.

Config-file layering

A running dsh tree is a {{term profile}} that stacks named {{term bundle | bundles}}. Patch files then overlay the result: a cordis.patch.yml file at each layer, plus any --patch overlays ({{cite apps/cli/src/profile-boot.ts:88}}). {{link learn/profiles-and-bundles}} explains the full, fixed layer order, with a diagram and a worked example. This page does not repeat it.

Main CLI flags

These flags belong to the dsh launcher itself, parsed in {{cite apps/cli/src/args.ts}}. The launcher stops reading at the first token it does not recognize, and hands everything after that to the booted profile's own app, verbatim ({{cite apps/cli/src/args.ts:5-9}}).

FlagMeaning
--profile <name>The profile under $DSH_HOME/profiles to boot ({{cite apps/cli/src/args.ts:168}}). dsh <name> is a shorthand for dsh --profile <name> when the first argument is not a flag and not plugin ({{cite apps/cli/src/args.ts:205-207}}).
--from-default-profile <name>Replaces a custom profile with a fresh copy of a shipped profile template before boot ({{cite apps/cli/src/args.ts:169}}).
--patch <path>Adds one extra patch-overlay file, applied after the profile's own layer. Repeatable; each use adds one more file, in argv order ({{cite apps/cli/src/args.ts:170}}).
--dump-config / --dump-default-config / --dump-config-schemaPrint the composed profile tree, the tree without the user layer and --patch overlays, or its JSON Schema, and exit without booting ({{cite apps/cli/src/args.ts:171-173}}).
plugin --profile <name> <pnpm-args...>Forwards pnpm arguments into one profile's own plugin dependencies, to add, remove, or query a plugin ({{cite apps/cli/src/args.ts:187-199}}).
