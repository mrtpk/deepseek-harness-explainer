Every turn and step boundary is appended to the session log. --- A {{term session}} has {{term turn | turns}}, a turn has {{term step | steps}}, and every turn or step boundary is appended to the {{term session-log | session log}}.

The idea

A {{term session}} counts its own work with a small, fixed vocabulary ({{cite docs/glossary.md:35-40}}). A {{term turn}} is one drain of admitted input. It opens before the first input is claimed, and it closes once nothing is owed ({{cite docs/glossary.md:37}}). A {{term step}} is one model request plus the tool calls its response causes. One turn has zero or more steps ({{cite docs/glossary.md:38}}, {{cite docs/architecture.md:81}}).

An everyday comparison. Think of a turn as one visit to a service counter. It stays open from the moment you are called until the clerk has nothing left to do for you. A step is one question you ask, and the paperwork it causes. The comparison stops here. A real clerk does not keep a permanent, numbered record of every step, but the session does: it appends one for each.

The picture

Read panel 2 left to right: the loop opens and closes a turn, and opens and closes each step inside it. It does this by appending one named event for each boundary. The session log on the right keeps every one of them, in order. Panel 1 names the pieces that build the agent this loop belongs to; {{link concepts/agent-loop-and-session}} reads it in detail.

In DeepSeek Harness

The agent loop's turn() method opens a turn by appending a turn/start event before it claims any input ({{cite packages/core/agent-loop/src/agent.ts:334-336}}).

Not every turn spends a step. Only when the turn's first claim rewrites to an empty message list, the loop ends the turn as completed and returns. No step/start event is appended at all ({{cite packages/core/agent-loop/src/agent.ts:356-361}}).

A {{term round}} sits outside a turn: it is an outer policy iteration, such as a goal round, that contains one turn ({{cite docs/glossary.md:39}}). The goal-round driver runs one such round each time it admits automatic continuation work for a session ({{cite packages/goal/goal-round-driver/src/index.ts:2}}). An {{term exchange}} is a run of consecutive turns, from a turn that admits human input until the next such turn ({{cite docs/glossary.md:40}}). The Web chat client groups turns into exchanges the same way, to decide which run of turns stays visible on screen ({{cite packages/client/ui-chat/src/client/contract/group-tree.ts:6-7}}).

Every append, for every event type, goes through one method: Session.append(). It assigns the event the next sequence number, taken from the log's current length ({{cite packages/core/session/src/index.ts:827-833}}).

{{link concepts/agent-loop-and-session}} reads this same loop and log in more detail, including which object builds the agent that runs it.

More detail

A round's cap is a real config knob, not a fixed number. GoalService declares a defaultMaxGoalRounds setting, with a schema default of 256 ({{cite packages/goal/goal/src/index.ts:239-240}}). A new goal that sets no cap of its own gets this default when it is created ({{cite packages/goal/goal/src/index.ts:211-214}}, {{cite packages/goal/goal/src/index.ts:250-251}}). An exchange has no such knob. It is a read-only grouping the Web client computes from the turns already in the log, not a setting the session stores.

For the full generated service and event reference, see the repository's own {{cite docs/subsystems/core.md}} and {{cite docs/subsystems/session.md}}.

What can go wrong

Check for a logged step/start event before you assume the model was called. A turn can close as completed with no step at all, only when its first claimed input rewrites to an empty message list ({{cite packages/core/agent-loop/src/agent.ts:356-359}}).

This page only names the words. It leaves out every other reason a turn or step can end, such as a tool error, a cancellation, or a max-tokens limit. {{link concepts/agent-loop-and-session}} covers those.

Why it matters. Code that reads the session log to count an agent's work must use the right unit. Do not count turns when the question is about model calls: count steps instead.

How many steps can one turn have?

Zero or more. A step is one model request plus the tool calls its response causes, and a turn contains zero or more of them ({{cite docs/glossary.md:38}}, {{cite docs/architecture.md:81}}).

 What is the difference between a step and a round?

A step is inside a turn: one model request plus its tool calls. A round is outside a turn: an outer policy iteration, such as a goal round, that contains one turn ({{cite docs/glossary.md:38-39}}).

 Which event does turn() append before it claims the turn's first input?

turn/start. The loop appends it as soon as the turn number is set, before any input is claimed ({{cite packages/core/agent-loop/src/agent.ts:334-336}}).

 A turn's first claim rewrites to an empty message list. Does the loop still log a step/start event?

No. The loop ends that turn as completed and returns, only when this happens on the turn's first claim; no step/start event is appended ({{cite packages/core/agent-loop/src/agent.ts:356-359}}).
