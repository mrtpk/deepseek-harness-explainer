{{project name}} (dsh) is an open-source agent harness developed by DeepSeek AI ({{cite README.md:5}}). It is built on {{term cordis}}, an "everything-is-a-plugin" framework: every part of the product, including the model adapter, the tool registry, and the agent loop itself, is a plugin, replaceable from configuration ({{cite docs/architecture.md:9}}). This site explains the code at commit {{project short_sha}}. You need to know TypeScript and Node.js. You do not need to know Cordis or the agent-harness domain first: {{link learn/plugins-and-cordis}} starts there.

What it doesRuns an AI coding agent: a session, a turn/step loop against a model, a tool pipeline, and optional subagents, jobs and workflows ({{cite README.md:5}}, {{cite docs/architecture.md:9}}).
Runs onNode.js 24.9 or later, TypeScript, pnpm workspaces ({{cite AGENTS.md:84}}).
Code sizeMostly TypeScript/TSX, split across pnpm workspace packages under packages/ and apps/. See {{link code/index}} for exact counts.
Run itnpx @deepseek-ai/dsh web starts the Web UI at http://127.0.0.1:3080 ({{cite README.md:24}}, {{cite README.md:27}}).

The system map

One run starts at a surface, boots a profile, then reaches the core runtime. The core runtime can delegate background work. Each box below links to its page.

  • Surfaces. {{link tours/life-of-a-headless-task | the CLI}} answers one task and exits; the Web UI serves a browser at http://127.0.0.1:3080 ({{cite README.md:27}}); Desktop is an Electron window that loads the Web client's own packaged assets ({{cite docs/architecture.md:53}}).
  • Profile and bundle boot. A {{term profile}} stacks one or more {{term bundle | bundles}} into a plugin tree ({{cite docs/architecture.md:17}}, {{cite docs/architecture.md:19}}). {{link learn/plugins-and-cordis}} explains the plugin mechanism itself.
  • Core runtime. {{link concepts/agent-loop-and-session | the agent loop and session log}}, {{link concepts/tools-and-mcp | tools and MCP servers}}, and the LLM adapter answer one step at a time.
  • Delegation. The core runtime can hand work to {{term subagent | subagents}} ({{cite docs/architecture.md:138}}), background {{term job | jobs}} ({{cite docs/architecture.md:154}}), or a {{term workflow}} script ({{cite docs/subsystems/workflow.md:5}}).

The map leaves out the sandbox and approval layer, MCP servers, skills, and the SDKs and ACP server that let other programs drive a session. The concept pages under "Execution and safety" and "Protocols and clients" cover these.

  • Levels. Each page has a level: Beginner, Intermediate or Advanced.
